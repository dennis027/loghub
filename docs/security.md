# Security

[README](../README.md) · [Architecture](architecture.md) · [User guide](user-guide.md) · [Operations](operations.md) · [Security](security.md) · [Development](development.md)

Security model and hardening already in place, plus what to add for production.

**Elasticsearch security is on.** Each component has its own least-privilege account, created by the one-shot `setup` service ([observability/setup/bootstrap.py](../observability/setup/bootstrap.py)):

  | Account | Privileges |
  |---|---|
  | `logstash_writer` | `create_doc` / `auto_configure` on `logs-loghub-*` |
  | `grafana_reader` | read on `logs-loghub-*` |
  | `loghub_api` | read on `logs-loghub-*`, cluster monitor, `manage_ilm` |
  | `kibana_system` | Kibana's own service account |

  The `elastic` superuser is used only by setup and by humans. Graylog has a `loghub_reader` (Reader role) and Grafana a `loghub_viewer` (Viewer) for the API's health and search calls.
- **Secrets** are generated by `init-env.sh` into a `0600` `.env`, which is gitignored. Integration credentials are read from the environment and never stored in the database or sent to the browser. Webhook secrets are write-only.
- **Network:** UI and ingestion ports bind to `127.0.0.1` by default. PostgreSQL, Redis, Logstash's HTTP input, Fluent Bit's internal API input and Prometheus are not published (the dev override publishes Postgres and Prometheus on loopback). Graylog's OpenSearch and MongoDB sit on an `internal: true` network with no route out.
- **Graylog's OpenSearch runs without its security plugin**, as in Graylog's reference deployment. Isolation is network-level: only Graylog can reach it. For defense in depth, enable the plugin with TLS certificates and set `GRAYLOG_ELASTICSEARCH_HOSTS=https://user:pass@opensearch:9200`.
- **Masking:** passwords, tokens, API keys, Authorization/Bearer values and cookies are redacted **at ingest**, in Fluent Bit (all routes) and again in Logstash after JSON parsing. Organizations can add fields masked at read time and in exports, and viewers additionally don't see `user`, `client_ip` or `raw`.
- **Untrusted log content:** Angular renders log data only through text interpolation (no `innerHTML`), and a unit test checks that `<script>`/`onerror` payloads stay inert. nginx sends a strict CSP (`script-src 'self'`, `frame-ancestors 'none'`). CSV exports neutralize spreadsheet formulas. PDF reports escape cell content.
- **Query safety:** field names are validated, the `organization` field is off-limits, Lucene mode disables leading wildcards and caps automaton size, and every query has a 10 s server timeout and result caps (500 per page, 10,000 per export). Graylog results are post-filtered by organization.
- **API:** JWT with rotation and blacklist, throttles (login 10/min, search 120/min, export 20/h, ingest 1200/min per source), consistent validation errors, audit trail for logins (including failures), every create/update/delete, token rotation, exports and alert actions, with sensitive values redacted. The ingest endpoint validates batch size and shape, and overwrites tenant fields from the token.
- **Containers:** the API image runs as a non-root user. The frontend runs nginx unprivileged on port 8080. Log rotation is on (`json-file`, 10 MB × 3) and every service has a memory limit.
